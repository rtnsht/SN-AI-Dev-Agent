# v0.1.0-beta.1-hotfix.1 — Cloudflare RSC Cache Poisoning Fix

**Release Date:** 2026-03-23
**Severity:** High (user-facing, intermittent page breakage)
**Root Cause:** CDN cache poisoning — Cloudflare cached RSC flight data and served it as HTML

---

## Problem

Users intermittently saw raw React Server Components (RSC) flight data instead of the rendered page:

```
:HL["/_next/static/chunks/028725d28db1defe.css","style"]
:HL["/_next/static/media/70bc3e132a0a741e-s.p.woff2","font",{...}]
0:{"buildId":"eppCDXG4H3BGOlwgccVS1","tree":{...}}
```

## Root Cause

**Cloudflare CDN cached RSC flight data and served it for fresh HTML page loads.**

When Next.js handles client-side navigation, the browser sends an `RSC: 1` request header and the server responds with flight data (a compact streaming format for component trees) instead of full HTML. Cloudflare cached this response keyed only by URL, ignoring the `Vary: RSC` header. When a subsequent visitor (or the same user in a new tab) made a fresh page load without the `RSC: 1` header, Cloudflare served the cached flight data. Since no Next.js client runtime was loaded yet, the browser rendered it as raw text.

**Why Cloudflare ignores `Vary: RSC`:** Cloudflare only honors `Vary: Accept-Encoding` by default. All other `Vary` values are ignored per their documented cache behavior. This is a known platform limitation (see: https://developers.cloudflare.com/cache/concepts/cache-behavior/#vary-header).

**Why intermittent:** Different Cloudflare edge PoPs have independent caches. Whether the bug manifests depends on (a) whether an RSC response was recently cached at the user's PoP, and (b) the cache TTL, which varies by response.

## Fix

### Code Change (`webapp/next.config.ts`)

Added four cache-control headers to all dynamic routes (everything except `/_next/static/*`, `/_next/image/*`, `favicon.ico`):

| Header | Purpose |
|--------|---------|
| `Cache-Control: private, no-store, no-cache, must-revalidate` | Standard HTTP — prevents all proxy/CDN caching |
| `CDN-Cache-Control: no-store` | RFC 9213 — CDN-specific cache directive |
| `Cloudflare-CDN-Cache-Control: no-store` | Cloudflare-specific — takes highest priority in CF's cache hierarchy |
| `Vary: RSC, Next-Router-State-Tree, Next-Router-Prefetch` | Tells non-Cloudflare proxies to vary cache by RSC headers |

Also added `Cache-Control: public, max-age=31536000, immutable` to `/_next/static/*` — these are content-hashed and safe to cache indefinitely.

### Cloudflare Cache Rules (Dashboard)

Two rules added in Cloudflare Dashboard > rapps.ai > Caching > Cache Rules (allowlist strategy):

| Order | Rule Name | When | Then |
|-------|-----------|------|------|
| 1 | Cache static assets | URI Path starts with `/_next/static/` | Eligible for cache, Edge TTL = 1 year |
| 2 | Bypass everything else | All incoming requests (catch-all) | Bypass cache |

### Manual Step

Purge the entire Cloudflare cache after deployment to clear any existing poisoned entries:
Cloudflare Dashboard > rapps.ai > Caching > Configuration > Purge Everything.
